# Paper Assistant Next · 精读工作台

一个面向 Zotero 9 的中文 AI 论文阅读插件。它把「了解全文结构 → 定位难懂段落 → 翻译与解释 → 连续追问 → 回到原文核对」放在同一个工作台中，帮助你建立论文主线，而不只是得到一次性摘要。

当前源码版本：**2.3.1**。本项目与旧版 [zotero-paper-mind](https://github.com/lidayunzhongjun-cell/zotero-paper-mind) 使用不同的插件 ID、数据目录和更新源，不会覆盖旧版。

## 它能做什么

- **选段精读**：在 Zotero PDF 中选中一段，获取中文翻译、通俗解释、段内推理、全文中的作用，以及影响理解的专有名词说明。
- **连续追问**：保留每条阅读路径的问答历史；可以直接追问，也可以选中模型回答中的一句话，点击「引用追问」继续深挖。较早的对话仍保存在本机，但超出上下文预算时不会全部发送给模型。
- **PDF 全文图谱**：按章节—小节—段落组织提取到的全文，生成摘要、重要性判断、术语与关系，并能从图谱节点进入对应段落的精读会话。
- **AI 精炼稿导航**：把在 ChatGPT 等工具中生成的论文精炼稿（DOCX、UTF-8 TXT 或 Markdown）导入当前论文。可先用 **0 Token** 在本机建立完整结构导航，再选择最多 **1 次 API 调用**优化摘要、术语和关键关系。它与 PDF 图谱独立保存。
- **原文核对**：回答会说明本轮用到的材料范围。外部 AI 精炼稿始终标记为二手材料；图谱关系是辅助理解的推断，不冒充论文原文证据。
- **公式排版**：用本地 KaTeX 显示模型返回的 LaTeX 公式，并提供「公式复原」快捷提问。PDF 提取文字若已损坏符号，插件会要求模型标出歧义，而不能保证还原版面原貌。
- **阅读记录管理**：按论文保存路径、草稿、收藏和「已读懂」标记；可复制 Markdown 笔记、清空当前问答，或单独删除整条阅读路径。删除路径不会删除 PDF、图谱或其他会话。

## 安装

1. 从 [GitHub Releases](https://github.com/lidayunzhongjun-cell/paper-assistant-next/releases) 下载最新的 `paper-assistant-next-*.xpi`。若只想安装当前源码对应版本，请选择 `paper-assistant-next-2.3.1.xpi`。不要把 XPI 当作论文导入，也不要双击它安装。
2. 在 **Zotero 9** 中打开「工具 → 插件」，点击右上角齿轮，选择「从文件安装插件 / Install Plugin From File…」，然后选中 XPI。
3. 按 Zotero 提示重启。打开一篇 PDF 后，可从「工具 → Paper Assistant Next · 精读工作台」进入；在 PDF 中选中文字后，也可点浮动工具条的「精读 / 连续追问」。
4. 首次使用时，点击工作台右上角「API 设置」，填写接口地址、模型 ID 和 API Key，再保存。

已安装旧版 Next 时，使用同一插件 ID 的新版 XPI 升级即可，已有本机阅读记录会继续保留。原始项目的插件无需卸载；若两个项目的菜单让你混淆，可在 Zotero 插件管理中暂时禁用旧版。

> XPI 安装不需要 Node.js。仓库中的 `dist/` 是本机构建目录；以 Releases 页面实际发布的文件为准。

## API 设置

插件使用兼容 OpenAI **Chat Completions** 的接口。地址可以是服务商提供的 Base URL，也可以是完整的 `/chat/completions` URL；插件会为 Base URL 补上接口路径。例如 `https://api.deepseek.com/v1` 或本地服务的 `http://localhost:11434/v1`。模型 ID 必须与服务端支持的名称一致；本地无认证服务可以留空 Key。

API Key 保存在本机 Zotero 偏好设置中，**不是加密保险库**。问答会把问题、选段、必要的原文及有界历史发送给你配置的服务；PDF 全文建图会分批发送提取文字并产生多次调用。导入精炼稿本身只在本机解析，选择 AI 优化图谱后才发送相应材料。请在使用第三方服务前确认论文的保密要求和服务商政策。

## 推荐阅读流程

### 路线 A：直接从 PDF 建图

1. 打开论文的工作台，点击「建立 PDF 全文图谱」。确认发送范围和调用次数提示后再开始；首次建图可能较慢且消耗较多 Token。
2. 展开顶部的树状图谱，沿章节和段落查看主线、术语及原文。找到关键段落后点「精读 / 追问这一段」。
3. 点击「精读选段」并发送，再用「举个例子」「逐步推导」「核对证据」或自拟问题继续追问。重要结论请返回 PDF 原文核对。

### 路线 B：先用 AI 精炼稿快速导航

1. 在支持文件上传的 AI 中让它阅读论文，按[配套提示语](PROMPT-AI-SUMMARY-IMPORT.md)生成有章节顺序、论证单元和证据等级的精炼稿，并保存为 DOCX、UTF-8 TXT 或 Markdown。工作台左侧也可点击「复制精炼提示语」。
2. 在对应论文的工作台点击「导入 AI 精炼稿」。导入和解析不会调用配置的 API。
3. 想尽快看结构，点「本地建立精炼稿导航（0 Token）」；需要更凝练的摘要、术语与关系，再点「AI 优化精炼稿图谱（1次 API）」。超长文档发送的是各导航单元的有界样本，未发送部分仍保留在本地导航中。
4. 顶部「图谱来源」可切换 PDF 图谱和精炼稿图谱。精炼稿只是导航线索，关键结论仍以可核对的 PDF 原文为准。

### 管理会话和笔记

左侧「阅读路径」按选段或全文问答分别保存。切换路径不会改变其绑定的论文。每张路径卡片右上角的「删除」会在确认后永久删除该路径的选段、回答、收藏、草稿与读懂状态；「清空当前会话内容」只清除当前路径的问答，保留路径本身、选段与草稿。删除最后一条路径后会自动创建空白全文会话。

可以收藏回答、筛选收藏、标记读懂，点击「复制笔记」导出当前路径的 Markdown。回答中选中一句再点「引用追问」，比重新复制整段上下文更方便。

## 数据与能力边界

- 每篇论文的记录保存在 **Zotero 数据目录下的 `paper-assistant-next` 文件夹**，不会自动通过 Zotero Sync 同步。建议像备份文献库一样备份该目录。
- PDF 全文图谱依赖 Zotero 能提取到的文字。扫描版、图片、复杂图表、双栏与公式排版可能提取不完整；它不是视觉阅读或可靠 OCR。模型的总结、关系和术语解释也可能出错。
- 精炼稿图谱来自外部 AI 生成的二手材料，不等同于论文原文。导入它不会覆盖 PDF、PDF 图谱或既有问答；移除精炼稿只移除对应材料及其独立图谱。
- 0 Token 只指**本地建立精炼稿导航**不调用配置的模型 API；后续 AI 优化和问答仍会调用 API。PDF 全文建图不是 0 Token，也不保证只调用一次。
- 本机保存全部问答，但模型每轮只接收字符预算允许的最近完整对话及相关证据。插件不会静默把很早的历史当作已发送内容。
- 模型回答当前为非流式返回，可停止请求；停止或失败的回答保留状态供重试，不作为后续问答的有效证据。

## 开发与验证

需要 Node.js 和 npm。克隆仓库后在项目目录执行：

```powershell
npm ci
npm test
npm run build
npm run check:zotero -- --local
```

`npm run build` 会生成 `dist/paper-assistant-next-<版本>.xpi` 并执行打包检查。`check:zotero -- --local` 使用本机 Zotero 安装中的清单校验规则进行兼容性检查；它**不等于**在真实 Zotero 界面完成安装和功能验收。Windows 默认检查 `C:/Program Files/Zotero/omni.ja`，其他安装位置请查看 `scripts/check-zotero.mjs` 的参数说明。

主要代码位于 `src/`：`core.mjs` 处理会话与问答上下文，`graph.mjs` / `graph-runtime.mjs` 处理 PDF 图谱，`summary-graph.mjs` 处理精炼稿快速导航，`runtime.mjs` 处理 Zotero 数据与 API，`render.mjs` 负责安全排版，`ui.mjs` 负责工作台。

版本详情见 [更新记录](CHANGELOG.md)。问题和建议可提交到 [Issues](https://github.com/lidayunzhongjun-cell/paper-assistant-next/issues)。
