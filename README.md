# Paper Assistant Next · Zotero 论文精读工作台

Paper Assistant Next 是面向 Zotero 9 和 10.0.x 的中文论文阅读插件。它把 PDF 全文导航、选段翻译与解释、连续追问和原文核对放在同一个工作台中，目标是让你更快弄清论文的研究问题、方法、证据和局限。

当前源码版本：**2.3.5**。它使用独立的插件 ID 和数据目录，不会覆盖旧项目 [zotero-paper-mind](https://github.com/lidayunzhongjun-cell/zotero-paper-mind)。

## 主要功能

### 1. 从 PDF 建立全文图谱

点击「建立 PDF 全文图谱」后，插件先在本机提取并索引 Zotero 可读取的 PDF 文字，建立章节／小节／原文单元结构、BM25 全文检索、关键词、共词与引用候选，以及抽取式关键句。**这一步不调用模型 API**；图谱会先保存，之后可以展开节点查看对应原文，或直接从节点发起精读。

本地建图完成后，可以选择再用 **最多 1 次 API 请求**补全研究问题、核心方法、作者宣称的创新、主要结果、局限、术语和章节关系。为控制 Token，插件只发送经过本地索引选出的有界代表片段，而不是把整篇 PDF 发给模型。取消或增强失败时，本地图谱仍可用于检索与问答；稍后可点击「AI 增强 PDF 图谱」重试。

这里的“全文”指**本地索引覆盖提取到的文字**，不表示模型已经逐字读过未发送的部分。关键词、共词、引用候选和模型推断的关系都只是阅读线索，结论仍须回到 PDF 核对。

### 2. 选段精读与连续追问

在 Zotero PDF 中选中文字，点击「精读 / 连续追问」，即可把选段和论文绑定到一条阅读路径。你可以要求中文翻译、通俗解释、逐步推导、专有名词说明，以及这段在全文中的作用；也可以直接输入自己的问题。**不必先建立图谱才能选段提问**，但有图谱时，插件会先在本机检索相关原文，再把有界证据交给模型回答，不会额外调用一次模型来规划检索。

每条阅读路径保留问答历史。可以继续追问，或选中回答中的一句话后点「引用追问」，针对已有解释再次追问。工作台还提供「公式复原」「举个例子」「逐步推导」「核对证据」「自测理解」等快捷提问；模型返回的 LaTeX 公式由本地 KaTeX 排版。

### 3. 导入 AI 精炼稿（可选）

如果你已在 ChatGPT 等工具中让 AI 阅读论文并生成精炼稿，可以把 **DOCX、UTF-8 TXT 或 Markdown** 文件导入对应论文。左侧「精炼稿工具」中的两个按钮**只处理这份导入文档，不处理 PDF**：

- 「本地建立导航 · 0 Token」：按精炼稿的标题和内容建立可展开的导航，不调用配置的 API。
- 「AI 优化图谱 · 1 次 API」：可选地再整理精炼稿的摘要、术语和关系。精炼稿本身已经清楚时，通常无需重复优化。

精炼稿图谱与 PDF 图谱分别保存，可在工作台切换。精炼稿始终标记为**二手材料**，不能替代论文原文证据。[配套提示语](PROMPT-AI-SUMMARY-IMPORT.md)可帮助你生成适合导入的文档。

### 4. 管理阅读记录

按论文保存阅读路径、选段、草稿、问答、收藏和「已读懂」标记。可以只看收藏、复制 Markdown 笔记、清空当前会话的问答，或单独删除整条阅读路径。删除路径不会删除该论文的 PDF 图谱或其他会话。

## 安装与开始使用

1. 获取 `paper-assistant-next-*.xpi`：可查看 [GitHub Releases](https://github.com/lidayunzhongjun-cell/paper-assistant-next/releases)，或从源码执行 `npm ci`、`npm run build`，在 `dist/` 中取得当前版本的 XPI。发布页不一定与源码版本同步。
2. 在 Zotero 9 或 10.0.x 打开「工具 → 插件」，点击右上角齿轮，选择「从文件安装插件 / Install Plugin From File…」，选中 XPI，并按提示重启。**不要把 XPI 当作论文导入。**
3. 打开一篇 PDF，从「工具 → Paper Assistant Next · 精读工作台」进入；也可以先在 PDF 中选中文字，再点击弹出的「精读 / 连续追问」。
4. 要使用 AI 问答或语义增强，在工作台右上角「API 设置」填写接口地址、模型 ID 和 API Key。只建立本地导航时无需调用 API。

安装同一插件 ID 的新版 XPI 会升级已有 Next 插件，已有本机阅读记录会继续保留。旧项目的插件无需卸载。

## 如何选择阅读流程

**直接读 PDF：** 建立本地图谱 → 按需进行一次 AI 语义增强 → 从图谱找到关键段落 → 精读并追问 → 回原文核对。若只想解释眼前这一段，可以跳过建图，直接选段提问。

**已有外部精炼稿：** 导入文档 → 本地建立精炼稿导航 → 需要时才做 AI 优化 → 遇到关键结论回 PDF 原文核对。精炼稿流程不是 PDF 建图的必经步骤，也不需要两套图谱都建立。

## API、数据与能力边界

- 插件使用兼容 OpenAI **Chat Completions** 的接口。可填写服务商的 Base URL 或完整的 `/chat/completions` 地址；本地无认证服务可留空 API Key。
- PDF 本地建图为 **0 次 API 调用**；可选 PDF 语义增强最多 **1 次**，发送约 4.2 万字符以内的代表原文。精炼稿导入和本地导航为 0 次；其可选 AI 优化最多 1 次。后续每次 AI 问答仍会调用配置的服务，实际 Token 费用取决于材料和模型。
- API Key 保存在本机 Zotero 偏好设置中，**不是加密保险库**。问答会发送问题、选段、必要的原文及预算内的部分历史；使用第三方服务前请确认论文的保密要求。
- 每篇论文的记录保存在 Zotero 数据目录下的 `paper-assistant-next` 文件夹，**不会自动通过 Zotero Sync 同步**。请自行备份重要阅读记录。
- 图谱依赖 Zotero 能提取到的 PDF 文字；扫描版需要先 OCR。复杂公式、双栏、表格和图片可能提取不完整。公式排版不能保证还原 PDF 原貌；模型解释和图谱关系也可能出错。
- 所有问答保存在本机，但受上下文预算限制，较早的对话不会保证每轮都发送给模型。工作台会标明本轮使用的材料范围；未提供的原文不能视为已核对。

## 从源码构建与验证

开发需要 Node.js 和 npm。在本项目目录运行：

```powershell
npm ci
npm test
npm run build
npm run check:zotero -- --local
```

构建会生成 `dist/paper-assistant-next-<版本>.xpi`。本机兼容性检查只验证安装包及 Zotero 清单，不等于在真实 Zotero 界面完成安装和功能验收。版本变更见 [CHANGELOG.md](CHANGELOG.md)；问题可提交到 [GitHub Issues](https://github.com/lidayunzhongjun-cell/paper-assistant-next/issues)。
