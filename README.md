# Paper Assistant Next · 精读工作台 2.3.1

## 2.3.1：阅读路径可以独立删除

新安装包：`dist/paper-assistant-next-2.3.1.xpi`。

- 左侧每条阅读路径新增醒目的“删除”操作，不必先切换到该会话。
- 删除前会明确列出将移除的选段、回答、收藏、草稿和“已读懂”状态；PDF、知识图谱与其他会话不受影响。
- 删除正在查看的路径后自动切换到相邻路径；删掉最后一条时自动建立空白“全文导读与问答”，工作台不会进入无会话状态。
- “清除当前问答记录”更名为“清空当前会话内容”，与永久删除整条阅读路径明确区分。
- 删除操作先保存再更新界面；若本地文件保存失败，会恢复原会话和其中全部记录。

## 2.3.0：精炼稿快速建图，可选 0 Token 或最多一次 API 调用

新安装包：`dist/paper-assistant-next-2.3.0.xpi`。

此前“从精炼稿建立图谱”错误复用了 PDF 全文建图流水线，仍要逐批识别结构、逐段分析、逐章总结、汇总全文并抽取章节关系，因此请求次数多、速度慢，也没有发挥“总结已经凝练”的优势。2.3.0 改为专用快速架构：

- 标题层级、章节、小节、导航单元、字符位置和完整覆盖全部在本机确定，立即得到零 Token 的可用骨架。
- 新增“本地建立精炼稿导航（0 Token）”：完全不连接 API，直接用导入总结的标题与连续内容生成全面导航；之后仍可按需升级。
- “AI 优化精炼稿图谱（1次 API）”在本地骨架上补充更凝练的节点摘要、章节主线、术语与关键关系。
- API 固定最多调用一次，同时返回节点凝练、重要性、章节摘要、术语、主线和少量高价值关系；不再按章节追加请求。
- 普通精炼稿把完整内容放入这一次请求。超长精炼稿只发送每个导航单元的有界首尾样本，总材料约束在 42,000 字符以内；未发送的中部文字仍完整保留在本地图谱中，可以展开查看。
- API 返回非 JSON、缺少部分节点或请求失败时不自动重试：缺失字段用本机节点内容补齐，整体失败则保存本地完整导航，避免继续消耗 Token。
- 使用精炼稿图谱追问时，相关节点改由本机关键词、选段位置和图谱关系检索，不再额外调用模型做路由；通常每轮只剩最终回答的一次请求。
- 工作台分别显示 0 Token 本地导航和 1 次 API 优化两个入口，发送前明确说明调用次数和超长材料策略。
- 原来的 PDF 全文图谱仍使用严格的多阶段精读流程；本次优化只作用于已经由外部 AI 凝练过的导入文档。

升级后，已有精炼稿和旧图谱不会丢失。可先用 0 Token 入口立即重建导航；需要 AI 凝练和关系时再执行一次优化。

## 2.2.1：修复回答中的公式和数学符号排版

新安装包：`dist/paper-assistant-next-2.2.1.xpi`。

- 回答区新增本地 KaTeX 公式引擎，支持行内 `\\( ... \\)`、`$...$` 和独立成行的 `$$...$$`、`\\[ ... \\]`；分式、根号、求和/积分、上下标、矩阵、希腊字母、粗体向量和公式编号不再显示成摊平的源码。
- 20 个数学字体直接打进 XPI，不联网加载公式资源，也不会把公式发送给额外服务；宽公式可横向滚动，不再挤乱回答卡片。
- 模型指令要求保留原变量、上下标、上下限、括号、运算符和编号；PDF 提取结果不足以唯一恢复时必须列出歧义，不能把猜测排成“确定公式”。
- 快捷操作新增“公式复原”：专门让模型检查 PDF 文本提取破坏的符号，再用 LaTeX 重排并逐项解释。
- 已保存的旧回答只要本身含有上述 LaTeX 分隔符，升级后重新打开就会自动按新样式渲染；没有 LaTeX 的旧回答可点击“公式复原”重新生成。

说明：该修复能让模型返回的 LaTeX 接近论文的数学排版，但插件目前读取的是 PDF 提取文字，不是公式截图。若 PDF 已经把上下标、矩阵列或特殊字体丢失，任何模型都无法仅凭损坏文本保证与版面逐符号一致；新版会提示歧义而不是暗中猜测。

## 2.2.0：导入 AI 精炼稿，建立论文专属的独立图谱

新安装包：`dist/paper-assistant-next-2.2.0.xpi`。现在可以先把论文交给 ChatGPT 等支持文件上传的 AI，让它生成凝练的 `.docx`、UTF-8 `.txt` 或 `.md`，再把这份文档绑定到当前 Zotero 论文并交给已配置 API 建图。

- 工作台左侧新增“导入 AI 精炼稿”“从精炼稿建立图谱”“复制精炼提示语”“移除精炼稿”。导入时先在本机解析和检查，确认建图后才把文字发送到 API。
- 每份精炼稿按 Zotero PDF 附件独立保存。替换或移除精炼稿不删除 PDF、PDF 图谱和任何历史问答。
- PDF 全文图谱与 AI 精炼稿图谱使用两个独立缓存；顶部“图谱来源”可随时切换，不会互相覆盖。
- AI 精炼稿图谱会在界面、导出和回答上下文中持续标记为“二手凝练材料”。摘录只能证明精炼稿写了什么，不能冒充论文原文、页码或已核验引文。
- 使用精炼稿图谱追问时，先用精炼稿定位结构，再从 PDF 提取文字中检索相关证据；二者分字段发送给模型，冲突时要求以可核对的 PDF 原文为准。
- `.docx` 只读取正文，不读取页眉等附属内容；不支持旧版 `.doc`、加密/损坏文档、非 UTF-8 文本、过短或过大的总结，并会给出明确处理建议。

最合适的生成提示语已放在 [`PROMPT-AI-SUMMARY-IMPORT.md`](PROMPT-AI-SUMMARY-IMPORT.md)，工作台也可一键复制。建议让 AI 保留章节顺序、研究问题、方法、数据、结果、局限、稳定论证单元编号和术语，同时使用【论文明确】【AI归纳】【不确定】区分证据等级。

安装：Zotero 中打开“工具 → 插件 → 右上角齿轮 → Install Plugin From File…”，选择 `dist/paper-assistant-next-2.2.0.xpi`。若已安装旧版 Next，直接选择新 XPI 升级；插件 ID 不变，已有阅读记录保留。安装后重开工作台即可看到新按钮。

## 2.1.4：修复关键引文核验导致整份图谱失败

修复包：`dist/paper-assistant-next-2.1.4.xpi`。模型有时会改变空格、大小写、弯引号或破折号，也可能把概括误放进 `keyQuotes`，导致旧版报告“关键引文无法在对应段落中验证”。

2.1.4 对空白、Unicode 字形和常见排版标点做保守匹配；匹配成功后保存的始终是从当前段落反向定位得到的**论文原始文字**，不是模型版本。无法定位、被改写或疑似编造的可选引文会被忽略并显示数量提示，段落摘要和整份图谱继续构建。正文完整覆盖等结构校验不受影响。

## 2.1.3：修复无效关系导致整份图谱失败

修复包：`dist/paper-assistant-next-2.1.3.xpi`。2.1.2 之后发现模型有时把片段 ID（如 `p2.1`）作为关系目标，或者返回不存在的段落、自关联、缺失关系类型/依据，触发“关系指向不存在的段落或缺少说明”。

2.1.3 将可确定的 `pN.M` 自动归一到父段落 `pN`；目标不存在、同段自关联、目标未在本批材料中出现、缺少类型或具体依据的可选关系会被忽略并显示数量提示。正文完整覆盖、段落摘要、关键引文真实性和术语校验仍然严格，单条可选推断关系不再毁掉整次已经完成的精读结果。章节之间的可选关系采用同样的容错原则。

## 2.1.2：修复跨批次关联位置异常

修复包：`dist/paper-assistant-next-2.1.2.xpi`。通过 Zotero 的“工具 → 插件 → 从文件安装插件”升级后，对之前失败的论文重新点击“建立全文知识图谱”。

2.1.1 对跨批次同一段落的章节和小节标题使用逐字比较。模型只要在下一批省略编号、改变空格或换一种同义表述，即使原文位置连续，也会报告“跨块段落延续与章节位置不一致”并终止建图。2.1.2 改为由不可变的原文字符范围和延续标记确定连接，并继承上一批已经确认的章节路径；批次刚好切在同一物理文本行内部时会直接判定为延续。不会因此增加 API 重试或额外计费调用。

新增三层回归验证：路径名称漂移修复、长文本行跨批强制延续、完整多批建图流程。仍保留完整原文覆盖、无重叠以及未知关系节点等严格校验，不会为了绕过错误接受丢失内容的图谱。

## 2.1.1：三个独立清除入口

历史本地测试包：`dist/paper-assistant-next-2.1.1.xpi`。

- “清除当前问答记录”位于“建立全文知识图谱”上方：只清除当前会话的问答及这些回答的收藏，其他会话、图谱、选段、草稿和读懂标记保留。
- “清除全文缓存”位于建图按钮下方：清除当前论文的提取原文缓存、知识图谱、术语和全文导读；保留 PDF 文件、全部会话及问答。下次问答可重新提取原文，图谱需要手动重建。
- “清除本段缓存”位于锁定原文下方：仅选中段落会话时出现。需要唯一定位到图谱段落才能点击；选段匹配多段时，须从图谱进入某个具体段落。清除该节点的摘要、重要性/密度、关键引文、术语关联和相关语义关系，保留原文位置、章节结构及其他段落。对应章节摘要、章节语义关系及全文串联随之失效，防止继续使用已经清除的分析。

清除前显示范围确认；请求进行中禁止清除。保存失败会恢复被清除的数据。清缓存不删除问答，清问答不删除缓存。清除后状态保存在本机，重开不会恢复已清除内容；重新建图会重新生成缓存。

## 2.1.0：章节—小节—段落树状知识图谱

本地测试包：`dist/paper-assistant-next-2.1.0.xpi`。尚未发布到 GitHub；公共更新源仍保留已有正式版本。

- 先按全文文字行识别章节、小节与自然段，验证连续覆盖且没有遗漏或重叠。每个段落保留原文字符起止位置；跨批段落可合并。
- 逐段评判重要性、信息密度及上下文作用；低重要性用一句话，高重要性保留论证、条件和可核验的关键引文。
- 保存章节、小节、段落的包含关系、原文顺序和带依据的语义关系；语义关系标记为模型推断。术语独立存储，通过段落 ID 关联，保留不同语境下的不同解释。
- 全部段落摘要逐级串联为章节认识和全文认识。图谱、完整提取原文、问答一同保存到本机，重开后可继续使用。
- 追问先匹配选段，再用全文概览、章节索引、候选段落、关系和术语进行一次模型检索预判，然后读取选定段落及相关节点的原文作答。定位失败、重复匹配、截取片段和路由降级均明确标注。
- 点击工作台上方“全文精读 · 树状知识图谱”展开章节及段落；每段可查看原文并创建精读会话。可复制完整 Markdown 图谱及术语表。

首次构建会多次读取全文并调用模型，比旧版粗摘要更慢、用量更高。后续追问只发送有预算的图谱与原文区域，完整原文保留在本地可检索，**不每次整篇发送**。每次图谱追问通常需要一次路由调用加一次回答调用，不能保证所有问题都比旧版更快。预算以字符计，不是精确 token。跨章原文材料设总量与单段预算，长段会明确标记为节选。

结构依赖 PDF 文字提取和模型识别，双栏、页眉、跨页、扫描件可能影响段落边界；不保证与排版中的自然段逐一相同。图表视觉和 OCR 尚未实现。无标题内容采用明确的描述性标题；更深层小节用标题路径保留。旧版记录仍可读取，但须重新建立图谱才能启用图谱检索。构建失败/停止不会替换已保存图谱，不自动重试产生额外模型调用。跨批次同一段落会继承前一段的章节路径，避免模型重复标题的空格、编号或措辞变化误触发位置异常。

本地验证：`npm test`、`npm run build`、`npm run check:zotero -- --local`。最后一项读取本机 Zotero 的清单校验代码；`--local` 不要求尚未发布的测试版出现在公共更新源。下面保留 2.0.x 的历史功能和安装说明，全文导读入口在新版更名为“建立全文知识图谱”。

面向 Zotero 9 的 AI 论文精读助手：先让模型建立全文导读，再对选中段落进行中文翻译、通俗解释、全文作用分析和术语拆解，并围绕任意回答连续追问。

这是独立于 [`zotero-paper-mind`](https://github.com/lidayunzhongjun-cell/zotero-paper-mind) 的新项目。目标是减少阅读时的跳转、重复解释和上下文丢失。它使用独立插件 ID、存储目录和更新源，不覆盖旧版，可与旧版并存或随时回退。

## 核心能力

- **全文导读**：提取论文文字，分层生成研究问题、贡献、论证路线、方法、局限和建议阅读顺序。
- **选段精读**：一站式获得中文翻译、通俗解释、在全文中的作用与组成，以及关键专有名词说明。
- **真正的多轮追问**：保留完整问答记录，可继续追问，也可引用模型回答中的一句话再问。
- **证据约束**：优先使用选段附近和检索到的论文原文，并明确说明模型实际拿到了哪些材料。
- **阅读工作台**：每篇论文独立保存会话、草稿、收藏和“已读懂”标记，支持回到原文与 Markdown 笔记导出。
- **开放 API**：兼容 OpenAI 风格的 `/chat/completions` 接口，可配置云端模型或本地模型服务。

> 隐私提示：插件会把生成回答所需的论文文本、问题和最近对话发送给你配置的 API 服务；Key 保存在本机 Zotero 偏好设置中，阅读记录保存在本机 Zotero 数据目录。

## 安装

1. 在 [Releases](https://github.com/lidayunzhongjun-cell/paper-assistant-next/releases/latest) 下载最新的 `paper-assistant-next-*.xpi`。
2. 打开 Zotero 的 **工具 → 插件**（Plugins）。
3. 点击右上角齿轮 **Tools for all plugins → Install Plugin From File…**。
4. 选择下载的 XPI（不要再选择有安装缺陷的 2.0.0）。
5. 安装后，在 **工具 → Paper Assistant Next · 精读工作台** 打开新界面。不要双击 XPI，也不要通过“导入文献”安装。
6. 打开一篇 PDF；选择原文，浮动工具条会出现 **精读 / 连续追问**。右键菜单也可打开工作台。
7. 在工作台右上角 **API 设置** 中确认地址、模型与 Key。若旧版已有配置，新版会读取作为默认值；保存只写入新版配置。

地址示例：`https://api.deepseek.com/v1`、`http://localhost:11434/v1` 或完整的 `/chat/completions` 地址。非标准网关请填写服务商提供的完整路径。本地无认证服务可留空 Key。

旧版不用卸载。如果同时显示两套菜单影响阅读，可以暂时禁用旧版，只保留 Next；随时可以切回。

### 2.0.1 安装修复

2.0.0 的清单遗漏了 `applications.zotero.update_url`。本机 Zotero 9.0.6 的 `Extension.sys.mjs` 将其视为必填字段，因此拒绝安装并显示笼统的“不兼容”提示。2.0.1 补齐该字段；继续使用适配本机的 `9.0`—`9.*` 范围，没有通过放宽版本上限绕过问题。

构建现在强制检查 Zotero 清单必填字段，并加入缺字段回归测试。`npm run check:zotero` 会只读提取本机 Zotero 的这一段校验代码：2.0.0 被拒绝，2.0.1 通过。它不等于在 Zotero 界面完成了安装验收。

更新地址指向本仓库根目录的 `update.json`，安装后的版本可通过独立更新源获取新版本，不会混用旧插件更新。

## 推荐阅读流程

1. **先抓主线**：点击“建立全文导读”。提取本地 PDF 文本后显示字符量与预计最低请求次数；确认后才分块发送。结果包括问题与贡献、论证路线、方法、局限和建议阅读顺序。中途可停止。
2. **再解卡点**：选中读不懂的段落，打开“精读 / 连续追问”。点击“精读选段”填入问题，再点发送。
3. **沿问题追下去**：直接输入“为什么”“再举个例子”，历史成功问答会发送给模型。不是覆盖上一条回答。
4. **针对一句话追问**：在某条回答中用鼠标选中一句话，点击该条回答下的“引用追问”；不选文本则引用整条回答。引用会显示在输入框上方，可取消。
5. **留下能复习的东西**：收藏重要回答，标记“已读懂”，或“复制笔记”导出当前会话的全部 Markdown。自测按钮先只生成题目，回答后可以继续让模型检查。
6. **返回原文核对**：点击“回到原文”。若选段事件含页码，则定位该页；否则只打开对应 PDF，不伪造位置。

| 连续追问 | 新回答覆盖旧回答，模型缺少问答历史 | 成对发送历史问答；无限追加本地阅读记录 |
| 针对回答提问 | 需要自己复制、解释指代 | 每条回答都可引用追问，显示被引用内容 |
| 来源绑定 | 追问时再识别当前论文，切 PDF 易混淆 | 按文献库 ID + PDF 附件 key 固定论文，每个选段独立会话 |
| 回答结构 | 大文件中的手写解析与多次样式覆盖 | 核心结论突出，翻译/推理展开，术语/边界可折叠 |
| 证据 | 主要依赖阅读摘要 | 摘要 + 选段附近原文 / 关键词检索原文，明确显示材料范围 |
| 阅读记录 | 追问无持久历史 | 按论文保存会话、草稿、收藏与读懂标记，重开可恢复 |
| 文件位置 | 写死开发机器 D 盘目录 | 存在 Zotero 数据目录的 `paper-assistant-next` 文件夹 |
| 长论文 | 多阶段笔记可能整体拼接过大 | 全文字块完整覆盖，分层合并；超限明确报错，不静默截断 |
| 请求故障 | 主要显示报错文本 | 停止、超时、保留失败记录、重试，失败回答不进入后续上下文 |
| 回看 | 反复开结果窗口 | 每篇论文一个可复用窗口，选段会话列表、收藏筛选、大字与专注模式 |

## 发布文件与回退

- Release 中的 `paper-assistant-next-2.0.1.xpi`：可直接安装的插件包。
- 源码构建后的 `dist/reading-workspace-preview.html`：浏览器可打开的静态设计示例；非实际模型回答，仅折叠、专注与大字交互可用。
- 新版不写旧版缓存，也不自动导入可能来源不明确的旧摘要；首次使用新版需重新建立全文导读。

若要回退：禁用 Next，重新启用旧版。旧版缓存、API 设置和代码均保留。新版历史无需删除，重新启用后仍可读。

## 当前验证范围与限制

- 通过 Node 自动测试：多轮消息、历史裁剪、引用、论文材料边界、排版转义、失败/停止、磁盘写入顺序与恢复。
- 构建会检查 XPI、Zotero 清单必填字段与脚本路径，并在模拟 Zotero 宿主中执行安装包内的 bootstrap → startup → shutdown，验证菜单和选段事件注册。另已使用本机 Zotero 9.0.6 的相关清单校验代码验证此修复。
- **本轮没有在真实 Zotero 中完成安装验收，也没有使用你的 Key 发起付费模型调用。** 模拟宿主验证不能替代真实 Zotero UI 测试。
- 只支持文字提取，扫描版需 OCR；不会“看到”图表、复杂公式排版或图片。导读基于全部提取文字的分块阅读，不保证等同于人类通读 PDF。
- 本地保存全部轮次，但每轮只发送字符预算内最近的完整对话。较早消息不发送时会在回答材料说明中标出。字符预算并不等于模型 token 预算，小上下文模型仍可能需要缩小选段。
- 当前非流式返回；生成过程中显示状态并可停止。复杂公式按原始文本显示，暂未集成 LaTeX 数学排版。
- 自动保存到本机，不通过 Zotero Sync 同步；草稿在离开输入框、切换会话或关闭窗口时保存。文件损坏会报错并保留原文件，不静默覆盖。
- 插件 API Key 保存在本机 Zotero 偏好设置中；论文文本与历史保存在本机数据目录，回答请求会发送必要资料至配置服务。

## 开发

```powershell
cd paper-assistant-next
npm test
npm run build
npm run check:zotero
```

先运行 `npm install` 安装锁定版本的构建依赖。正式发布构建应使用本项目的 `package-lock.json`。安装 XPI 不需要 Node 或开发依赖。

`check:zotero` 默认读取 Windows 的 `C:/Program Files/Zotero/omni.ja`；自定义安装位置可用 `npm run check:zotero -- "你的 Zotero 安装目录/omni.ja"`。此命令不修改 Zotero 安装目录、用户配置或文献数据，也不启动或关闭 Zotero。

模块划分：`core.mjs` 负责会话与上下文；`runtime.mjs` 负责 Zotero 数据、存储与 API；`render.mjs` 负责安全排版；`ui.mjs` 负责工作台交互；`main.mjs` 和 `bootstrap.js` 负责宿主生命周期。
